Agent & Automation Role Map

I do not treat every scheduled process as an “agent.” Known paths stay deterministic. Agentic tasks are reserved for bounded work where interpretation or synthesis adds value. Data workers supply context, outputs consolidate attention, and consequential decisions return to a human gate.

Design Rules the boundaries are part of the architecture

Work typeDefault patternEscalate to human when
Known, repeatable path Deterministic workflow with explicit inputs and outputs Required data is missing, validation fails, or the next action changes a commitment
Research / synthesis Bounded agentic task with a defined objective and evidence requirement The recommendation affects spend, customer commitments, risk, or production systems
External action Tool call or workflow after the decision is authorized Scope is ambiguous, permissions change, or the requested action exceeds delegated authority
Learning / state Write verified outcomes and preferences back to the shared knowledge layer New learning would overwrite source-of-truth records or alter protected governance state
Why this matters. The architecture is intentionally mixed: agentic where judgment helps, deterministic where rules are known, and human-gated where consequences matter. That separation is a design choice, not a naming convention.
