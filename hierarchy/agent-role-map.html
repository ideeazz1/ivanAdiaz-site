The map explains responsibilities and work patterns, not current schedules or proof that every component is active. Implementation, testing, deployment and accepted results need their own evidence.

Design Rules the boundaries are part of the architecture

Work typeDefault patternEscalate to human when
Known, repeatable path Deterministic workflow with explicit inputs and outputs Required data is missing, validation fails, or the next action changes a commitment
Research / synthesis Bounded agentic task with a defined objective and evidence requirement The next action requires spending, external commitments, publication or a protected production decision
External action Tool call or workflow after the decision is authorized Scope is ambiguous, permissions change, or the requested action exceeds delegated authority
Learning / state Write verified outcomes and preferences back to the shared knowledge layer Evidence is uncertain or a proposed change exceeds authorized scope
Why this matters. The architecture is intentionally mixed: agentic where judgment helps, deterministic where rules are known, and human-gated where consequences matter. That separation is a design choice, not a naming convention.

Implemented versus planned: a design or prototype is not a deployment. Tests establish their stated checks; an operating result needs observation and acceptance. Read the evidence distinctions.
