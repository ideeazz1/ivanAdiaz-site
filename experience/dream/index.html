How the operating system runs

A small company of agents, with rules.

Dream is the memory. Around it sits an operating system with one loop: observe, decide, delegate, execute, verify, learn, persist, continue.

  • Two roles that never overlap

    One AI manages the work and dispatches it. A different AI reviews the exact change and accepts it. No one accepts its own work.

  • One ledger of work

    Every priority lives in a single work file with an outcome, a scope and acceptance criteria. Reports never override it.

  • Receipts, not claims

    Every run publishes a receipt. A run without one is reported as missing, and a failed run records its error, cause and fix.

  • Owner-only gates

    Spending, client contact, publishing as me, credentials and anything irreversible wait for my decision.

Replace, don’t add

Instructions are controlled like code.

Agents may fix their own code and data handling. They may not change the rules they run under. A rule change needs my recorded approval, names the text it replaces, and is tied to a real, dated mistake it prevents. Start loose; tighten only after a real mistake.

Mistakes as events

Every chat leaves a trail.

My working chats are captured in my own words: the mistakes, the decisions and the ideas, each dated. Sadie, my learning assistant, rereads them and writes down patterns in how I work. Those patterns inform an agent’s judgment; they never become a new rulebook.

Where we need to improve

What isn’t
proven yet.

Enforcement isn’t complete. Several instruction locations live outside GitHub and are not yet independently verified, so I don’t claim full protection there.

The learning is real but unmeasured. I can show captured lessons and changed rules; I can’t yet show a measured drop in repeated mistakes.

The cost of AI work is watched closely but not fully instrumented. Unknown cost stays unknown instead of being estimated.

For hiring teams and partners

Why this
matters to you.

  • Operations design. I turn messy, daily work into clear roles, schedules and acceptance criteria.
  • Governance without bureaucracy. Few rules, each tied to a real failure, with an owner who approves change.
  • AI that is accountable. Independent review, receipts and read-back before anything is called done.
  • Cost and risk awareness. Spending, client contact and irreversible actions stay with a person.

My part in the system

I own the decisions.

I choose what gets built, define the work and accept or reject the result. AI agents implement most of the code.

Dream is built around GBrain’s memory process. Sadie uses captured lessons to suggest ideas. An idea still needs a decision.

The goal is fewer repeated mistakes. That improvement has not been measured. This page explains the design; it is not a live activity report.
